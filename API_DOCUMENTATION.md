## Note sulla Consistenza

### Consistenza Stretta (Strict Consistency)
- **AuthService.register()**: MongoDB e Neo4j aggiornati in transazione, rollback se Neo4j fallisce
- **ReviewService.createReview()**: Review salvata in MongoDB, ReviewNode creato in Neo4j con relazioni. Se fallisce: rollback MongoDB
- **ReviewService.deleteReview()**: Eliminazione da entrambi i database in transazione
- **ProfileService** operations: Aggiornamenti username/delete propagati a Neo4j immediatamente

### Consistenza Eventuale (Eventual Consistency - ASYNC)
- **Statistiche aggregate**: stats_per_year, average_rating, likes_count aggiornate in modo asincrono
- **Snapshots**: recent_reviews_snapshot, popular_reviews_snapshot aggiornate in background
- **Propagazione username**: Aggiornamento username in review documents e book snapshots (ASYNC)
- **Month score**: Calcoli per trending books aggiornati in background

## Pattern di Query Ottimizzati

### MongoDB Patterns
1. **Extended Reference Pattern**: Bookshelf denormalizza title, author, genres per evitare JOIN
2. **Array Operations**: $addToSet, $pull, $push con $slice per gestire collections embedded
3. **Positional Updates**: Operatore $ per update elementi specifici in array
4. **Linked Lists**: User.reviews array usato per query efficienti invece di scan su user_id
5. **Aggregate Statistics**: Contatori denormalizzati (ratings_count, sum_ratings) per calcoli veloci

### Neo4j Patterns
1. **Get or Create**: Pattern MERGE per evitare duplicati nei nodi
2. **Relationship Properties**: timestamp, since per tracking temporale
3. **Graph Traversal**: MATCH patterns per navigare relazioni sociali e likes
4. **DETACH DELETE**: Elimina nodi e tutte le relazioni automaticamente
5. **Index Lookup**: Tutti i nodi hanno mongoId per JOIN tra database

## Indici Utilizzati

### MongoDB
- **users**: _id (primary), username (unique), email (unique)
- **books**: _id (primary), title (text index per search)
- **authors**: _id (primary), name (text index per search)
- **reviews**: _id (primary), user_id (per user's reviews), book_snapshot.book_id (per book's reviews)

### Neo4j
- **User**: mongoId (unique constraint)
- **Book**: mongoId (unique constraint)
- **Author**: mongoId (unique constraint)
- **Review**: mongoId (unique constraint)
- **Genre**: name (unique constraint)
